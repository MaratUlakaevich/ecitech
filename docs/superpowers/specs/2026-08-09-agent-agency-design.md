# Агентство агентов ECITech — дизайн (2026-08-09)

## Назначение

Внутренняя AI-команда ECITech. Марат — CEO, управляет; агенты ведут продажи, маркетинг, разработку и операционку. Не продукт на продажу и не витрина (упаковка в кейс — возможна позже, но не требование дизайна).

Главный контекст: активный [[План — lead generation Gulf при нулевом бюджете (2026-08-09)]] — 2 закрытых проекта к 2026-09-20, единственная метрика недели — отправленные касания. Агентство строится так, чтобы **ускорять** этот план, а не откладывать его.

## Утверждённые решения

| Вопрос | Решение |
|---|---|
| Назначение | Внутренняя команда (CEO-режим для владельца) |
| Runtime | Гибрид: ядро в Claude Code + scheduled routines; 24/7-сервис — только для доказавшего ценность (Волна 4) |
| Автономия | Approval-first: всё внешнее (письма, посты) — через одобрение владельца; расширение автономии после 50–100 одобренных касаний |
| Очерёдность | Продажи → Маркетинг → Ops; разработка = формализация существующего Claude Code |
| Бюджет | До $50/мес сверх имеющегося; приоритет — email-гигиена (отдельный cold-домен + ящик) |
| Архитектура | «Штаб поверх Claude Code»: отдельный репо `ecitech_hq`, Notion CRM, Telegram-управление, scheduled routines |

## Оргструктура

Владелец взаимодействует через две точки: **Telegram** (утренний бриф, очередь approvals, алерты) и **Claude Code** (постановка задач, стратегические сессии). Каждый агент — «сотрудник» с файлом-досье: роль, инструменты, плейбук, guardrails, KPI.

### Отдел продаж (Волна 1)

| Роль | База | Функция |
|---|---|---|
| Lead Scout | новый | Поиск лидов по каналам A/B/D плана: агентства (Clutch/каталоги через Firecrawl), Gulf SME по триггерам (Apollo, MAGNiTT/Wamda), брифы на площадках. Apify / Vibe Prospector в рамках free tier |
| Lead Analyst | расширение `sales-triage` | Верификация, дедуп, обогащение, скоринг по схеме весов (бюджет 3 / срок 3 / ЛПР 2 / боль 2) → Notion CRM |
| Outreach Writer | на базе `alex-hormozi` | First-touch + follow-up (день 3 и 8), anti-AI-smell, Saudi-кейс в первом предложении Gulf-писем. Драфты → outbox на одобрение |
| Meeting Setter | новый | Cal.com booking-ссылки, подтверждения, pre-call brief (досье + повестка) за час до звонка |
| Closer Copilot | на базе `alex-hormozi` | Подготовка владельца: discovery-скрипт по CLOSER (Hormozi), разбор возражений, КП только для лидов 8+, follow-up после звонка. Финальное закрытие — человек |

### Отдел маркетинга (Волна 2)

- **Trend Scout** — мониторинг, что работает в нише AI + Gulf (WebSearch/Firecrawl).
- **Content Creator** — 3 LinkedIn-поста/нед + 1 статья в journal (канал E плана); на базе `content-strategist`/`content-analyst`.
- **Publisher** — готовит к публикации; публикует владелец (у LinkedIn нет API для личных аккаунтов).
- **Marketing Analyst** — недельный разбор: что сработало, коррекция контент-плана.

### Отдел разработки (только формализация)

Уже существует: Claude Code + feature-dev / code-review / vercel-скиллы. Фиксируем плейбуки Engineer / QA / DevOps в `departments/`. Новых агентов не строим.

### Operations (Волна 3)

- **Monitor** — аптайм сайта (Firecrawl monitor), CRM-гигиена, дедлайны, недельный статус.
- **Support** — драфты ответов на входящие клиентские письма (approval-first).
- **Finance** — инвойсы-драфты, cash flow в Notion; первая задача — вести блокер №0 (платёжный рельс, дедлайн 2026-08-16).
- **Optimizer** — ежемесячное ретро агентства; функция «Automate» (превращение повторяющихся процессов в routines) входит сюда.

### Сквозные ритмы

- Ежедневно утром: бриф в Telegram — пайплайн, очередь approvals, касания против плана, блокеры.
- Ежедневно: проверка follow-up (день 3/8).
- Пятница: недельное ревью с метриками (ритм плана продаж).

North-star Волны 1 — **отправленные касания/нед** (план: 75+). Нагрузка владельца — ≤ 30–60 мин/день на одобрения.

## Техническая архитектура

### Штаб — отдельный репозиторий `~/Work/ecitech_hq`

```
ecitech_hq/
├── CLAUDE.md              # устав: роль владельца, approval-first, ритмы
├── .claude/agents/        # досье агентов (lead-scout.md, outreach-writer.md, …)
├── .claude/skills/        # плейбуки-процессы (daily-leadgen, weekly-review, pre-call-brief)
├── playbooks/             # оффер, ICP, скрипты, шаблоны, скоринг — источник правды
├── departments/           # README отделов: роли, KPI, ритмы
└── outbox/                # очередь на одобрение: драфты писем/постов файлами
```

### Память (три слоя, ничего нового)

1. **Obsidian vault** — стратегия и решения (как сейчас).
2. **Notion** — операционные данные: CRM Leads (+ поля скоринга), позже Invoices.
3. **`playbooks/`** — рабочие материалы агентов.

Агенты читают vault, пишут результаты в Notion, драфты — в `outbox/`.

### Approval-цикл

Волна драфтов появляется в `outbox/` пачкой → владелец просматривает («одобряю 1,3,4, поправь 2») → отправка. Отправка вручную, агент готовит письма «под вставку» (25 писем/день не требуют sequencer). Последовательность ящиков: неделя 1 — существующий личный ящик (малые объёмы, тёплая сеть + первые агентства); параллельно заводится cold-домен и греется ~2 недели; с недели 3 холодные объёмы уходят на cold-домен, личный остаётся для тёплой сети и ответов. Telegram-бот — для брифов и алертов; до появления токена — файловый fallback (бриф падает в штаб).

### Бюджет до $50/мес

- Отдельный cold-домен (~$12/год) + ящик Zoho/Google ($1–7/мес) — не рисковать доставляемостью ecitech.online.
- Остальное — free tiers: Apify ($5 кредитов/мес), Firecrawl (подключён), Apollo (175 lead + 5000 AI кредитов).
- Апгрейд-точка: после первого закрытого проекта — Instantly/Smartlead.

### Scheduled routines (гибридная часть)

- Ежедневно утром: лидген-прогон (scout → analyst → writer → драфты в outbox) + бриф.
- Ежедневно: follow-up-проверка.
- Пятница: недельное ревью.

Запускаются облачными routines без участия владельца; результат ждёт в Telegram/outbox.

## Волны постройки

Критерий готовности каждой волны — бизнес-результат, не код.

| Волна | Срок | Скоуп | Definition of done |
|---|---|---|---|
| 0 | полдня | Штаб-репо, устав, Notion-поля скоринга, Telegram-бот (или fallback) | Штаб существует, бриф генерируется |
| 1 | 2–3 дня, к 2026-08-14 | 5 агентов продаж + 3 routines | 60 агентств в CRM, первая пачка из 25 писем одобрена и **отправлена** |
| 2 | неделя 2–3 | Маркетинг-конвейер (канал E) | 3 поста + 1 статья вышли |
| 3 | неделя 3–4 | Ops: Monitor, Finance, Support | Недельный отчёт пришёл автоматически |
| 4 | после первых денег | Вынос inbound-автоответа в 24/7 Agent SDK-сервис (апрельская архитектура SDR) | Автоответ на заявку < 5 мин без владельца; упаковка как flagship-кейс |

## Guardrails

- Никаких точных цен и сроков в письмах без владельца.
- Unsubscribe — мгновенно и навсегда (suppression list в Notion).
- Никогда не выдумывать кейсы, клиентов, технологии.
- Лимит 25 холодных писем/день с одного ящика.
- Стоп-сигнал плана: < 5% ответов на 300 касаний → переписываем оффер, не наращиваем объём (отслеживает Analyst автоматически).

## Риски

| Риск | Защита |
|---|---|
| Стройка вместо касаний (судьба TRACK M) | Волна 1 ограничена 3 днями; DoD = отправленные письма; утренний бриф показывает касания против плана каждый день |
| AI-smell в письмах | Approval-first + few-shot на реальных письмах + анти-шаблонные правила в плейбуке |
| Доставляемость домена | Отдельный cold-домен, SPF/DKIM/DMARC, лимит 25/день, прогрев 2 недели |
| Расползание скоупа (17 агентов сразу) | Волновая постройка; Волны 2–4 не начинаются, пока DoD предыдущей не достигнут |

## Метрики успеха (горизонт до 2026-09-20)

- Касаний отправлено/нед: 75+ (чекпоинты плана: 150 к 23.08, 350 к 06.09, 550 к 20.09).
- Время владельца на операционку: ≤ 1 ч/день.
- Пайплайн: 5+ квалифицированных разговоров, 1–2 закрытых проекта.
- Каждый лид в CRM имеет score и источник; 100% ответивших получают follow-up.
